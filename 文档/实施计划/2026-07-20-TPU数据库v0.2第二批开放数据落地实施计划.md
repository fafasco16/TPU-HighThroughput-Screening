# TPU 数据库 v0.2 第二批开放数据落地实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: Use the current environment's subagent-driven development workflow. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不创建训练集、不物化权重的前提下，将四个已由官方 API 核验为 CC BY 4.0 的高价值 PU/TPU 来源落地为可校验、可复跑、可分层计数的数据资产。

**Architecture:** 下载层只接受固定官方 HTTPS 端点、固定文件名、官方大小和 MD5，所有科学文件写入 `01_原始数据/外部数据/新增开放数据/` 的四个中文来源目录并受 Git 忽略。审计层按“化学体系—材料牌号—试样—采集—曲线—点”分层，只从实际文件复算，不把压缩包、图像、坐标轴、模拟帧或同一试样的多通道当作新增材料。治理层只登记资产、来源、引用、许可证和未来准入上限，保持训练拆分、训练权重与计算观测物化关闭。

**Tech Stack:** Python 3.12 标准库、固定哈希审计环境、只读 CSV/XLSX/ZIP 解析、pytest、PowerShell、Zenodo REST API、Figshare REST API、GitHub CLI。

### Task 2: 容器与科学语义审计

**Files:**

- Create: `代码/审计/新增开放数据第二批四源.py`
- Test: `代码/测试/test_audit_script_safety.py`

- [x] **Step 1: 实现通用容器硬门**

对每个 ZIP 执行 CRC、重复成员名、绝对路径、`..`、驱动器前缀、加密成员、压缩炸弹比例和解压总量检查；审计不在原始目录解压，只流式读取必要成员。输出只允许原子覆盖各来源的 `内容审计摘要.json`、`文件校验清单.tsv` 和按需 `曲线审计清单.tsv`。

- [x] **Step 2: 复算标准化弹性体来源**

先登记全部 10 种材料，再以材料名精确筛选 Filaflex 60A 与 Cheetah。分别统计拉伸、压缩、应力松弛、DSC/TGA/流变文件、物理试样、曲线和有限点；同一试样跨文件/模态同组，材料牌号是拆分下限。七个 ZIP 只提高模态覆盖，不得解释为七个数据集。

- [x] **Step 3: 复算 PU 微球复合材料最小包**

按文件名提取 0、5、10、15、20、25 vol% 六个条件和每条件两个物理试样；Machine 与 DIC 按试样绑定，Post 平均/平滑曲线只作派生视图。必须报告 12 个试样、各通道曲线/点数、六条条件均值和任何缺失/重复，禁止把 24 个通道或平滑曲线计作新增试样。

- [x] **Step 4: 复算高低速变形后应力松弛来源**

从 ZIP 实际文件名和表头识别两种商品双组分 PU、温度、预变形速率、松弛采集和重复；统计材料—工况组、物理试样、曲线和点。若配方仅为商品体系，则只进入速率/温度/本构迁移层，不能进入单体—性能主任务。

- [x] **Step 5: 复算 TPU 1301 本构来源**

将实验输入、参数标定、模拟输出、脚本、测试图像和派生图严格分开；统计实际实验工况、试样/曲线、模拟协议与输出，不把图像、网格点或时间步当作独立材料。只有可回连实验条件的模拟结果可作为本构迁移证据；单一 EOS TPU 1301 仍只算一个商业化学体系。

- [x] **Step 6: 连续双运行与输入不变门禁**

在哈希锁定审计环境连续运行两次，四源全部白名单输出 SHA-256 必须一致，所有科学输入运行前后哈希不变，且无残留 Excel/Python 进程。

## 自审结论

- 四源均已由官方 API 证明可获取、版本明确且为 CC BY 4.0；下载范围按信息增益而非总字节最大化。
- 26.9 GB 图像包被明确排除，因为 0.78 MB 数值包已经覆盖同一 12 个试样的机器/DIC/派生数据。
- 计划增加至少两种新的热塑弹性体牌号和三类高质量跨域力学/本构证据，但不会虚报为新的单体化学配方。
- 模拟输出可以纳入，但必须先闭合实验映射、协议和来源；本阶段不训练模型。
