# TPU 数据库 v0.2 剩余来源审计实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: use the current environment's subagent-driven development workflow. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将新增开放数据层尚未集中脚本化的 9 个来源全部纳入只读、确定性、可复跑的来源级审计，同时保持训练、拆分与权重物化关闭。

**Architecture:** 按解析技术和科学风险拆成四个互不写同一脚本的审计单元：核心/镜像 CSV、标准力学三源、工作簿双源、受限/专有格式双源。每个脚本只读取来源科学资产，只能原子覆盖来源目录内显式白名单的现有审计 JSON/TSV；公共安全测试、文档计数和最终双构建由主任务统一收口。

**Tech Stack:** Python 3.12 标准库、`openpyxl`/`xlrd`/`pandas`（来自独立哈希锁审计环境）、Windows Excel COM 只读辅助脚本、pytest、PowerShell、GitHub CLI。

## 统一输出契约

每个来源沿用现有文件名，不创建第二套事实：

- `内容审计摘要.json` 或来源已采用的 `数据审计摘要.json`；
- `文件校验清单.tsv` 或已有等价校验清单；
- `曲线审计清单.tsv` / `曲线解析清单.tsv` / `解析状态清单.tsv`（仅来源已有该层时）。

所有 JSON 使用 UTF-8、`ensure_ascii=False`、排序键和固定缩进；所有 TSV 使用 UTF-8、LF、固定列序。审计基准日写协议常量，不读取当前时间。临时文件必须位于目标文件同目录，完成 `flush + fsync` 后 `os.replace`；目标目录或文件是符号链接/重解析点时立即失败。脚本连续运行两次必须得到相同 SHA-256，并证明科学输入哈希未变化。

## 自审结论

- 9 个缺口来源均有唯一实现任务，没有来源遗漏。
- 四个脚本边界互不重叠，智能体不会写同一实现文件。
- 核心数据、镜像、标准曲线、旧版 Excel、大型 OOXML、专有格式和许可缺失均有明确失败策略。
- 计划不创建训练集、不物化权重、不绕过访问或许可限制。
