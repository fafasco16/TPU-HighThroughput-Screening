# TPU 高通量筛选数据库 v0.1 设计规范

**日期：** 2026-07-18  
**状态：** v0.1 数据工程基线已实施并通过验证
**主研究路线：** 线性分段 TPU 的“时序耗散—延迟有序化”筛选，在高韧性之外同时约束滞后、循环恢复与加工窗口。  
**证据总台账：** [`TPU_数据来源与研究路线台账.md`](../TPU_数据来源与研究路线台账.md)
**GitHub 私人仓库：** [fafasco16/TPU-HighThroughput-Screening](https://github.com/fafasco16/TPU-HighThroughput-Screening)（`PRIVATE`，默认分支 `main`）

## 1. 决策摘要

数据库 v0.1 只解决一个边界清晰的问题：把当前已经取得的数据转化为**来源可追溯、许可证可审计、单位一致，并能为后续防泄漏机器学习提供谱系基础**的数据层。它不在本阶段运行 DFT/MD、训练终模型或宣称已经得到可合成的新体系；SMiPoly 条目只作为规则约束的虚拟候选结构。

推荐采用“**不可变源文件 + 分源适配器 + Parquet 规范表 + DuckDB 查询快照 + Excel 人工审核目录**”的混合架构：

- `01_原始数据/` 中的第三方文件保持只读，不重命名、不覆盖其内部结构。
- 每个来源独立抽取到 `02_暂存数据/`（逻辑层 `staging`），保留原始字段、单位、sheet/文件位置和行号。
- `03_规范数据/`（逻辑层 `curated`）采用规范化长表，不把配方、试样、测试条件和曲线塞进一张宽表。
- DuckDB 是机器查询入口；Parquet/快照 JSON 是可版本化、可哈希复核的确定性基准。DuckDB 由 Parquet 重建，不作为字节级快照身份。
- Excel 只作为人类审核、许可证清单和质量总览，不作为唯一数据库。

## 2. 范围与成功标准

### 2.1 v0.1 已实现范围

1. 1,606 个原始文件的文件级清单、SHA-256、相对路径与默认拒绝许可状态；其中 4 个结构化来源补充 DOI/URL、访问日期、许可证与再分发状态。
2. 四个端到端垂直切片：SMiPoly 虚拟候选结构、PUE 变换后辅助特征、Eom 2021 氢键 TPU 曲线/标量、预聚体温度—黏度曲线。
3. 统一的来源、来源文件、候选结构、辅助特征、标量性能、曲线、曲线点与派生指标表；尚未建立完整的配方、批次、试样和测试实体链。
4. 对 16 条合格拉伸曲线派生拉伸强度、断裂伸长率和曲线下面积，共 48 条计算指标；初始模量、滞后、残余应变和循环保持率尚未纳入本版派生管道。
5. PUE 母记录谱系字段、曲线级原子分组、自动质量检查、许可证发布白名单、确定性快照和人工审核目录。

### 2.2 本版本明确不纳入

- 不把 PI1M、SMiPoly 假想结构冒充实验 TPU 数据。
- 不把 PolyOmics、ADEPT、PolyGraphMT 等计算数据与实验标签混成同一 fidelity。
- 不把商业牌号、打印几何、复合材料或交联 PUE 当作配方已知的线性 TPU。
- 不把 CC BY-NC-ND 或其他禁止演绎/再分发的数据并入可公开训练数据包。
- 不对缺失配方、缺失测试条件或扫描图数据进行无证据填补。
- 不在 v0.1 开始大规模 DFT、MD、生成模型训练或实验合成。
- 不把 Nature 2025 DCR、4TU SH-TPU/FDM、Jiang 2021、Li 2026、商业 TPU 曲线等已取得但尚未映射的来源描述为已结构化。
- 不把尚未实现的 `formulation`、`synthesis_batch`、`specimen`、`test` 实体或完整材料族/近重复泄漏审计写成当前能力。

### 2.3 验收标准

- 100% 清单文件具有稳定 `source_file_id` 和 SHA-256；4 个结构化输入具有来源、访问日期和许可证状态。
- `03_规范数据/` 中 100% 的规范记录可以追溯到源文件、sheet/表格、原始记录或曲线文件。
- `03_规范数据/` 中的规范表不存在孤立外键或重复主键；单位证据不足的记录显式保留为 `unresolved` 并产生 QC 警告，不伪造规范单位。
- 单位可解析曲线同时保留原始数值/单位与规范数值/单位，转换规则可复算；未解析曲线不得参与当前派生指标或后续训练候选。
- 公开发布视图不包含许可未知、非 `available` 或访问限制非 `open` 的记录；“可公开”只表示通过发布门，不等于单位已解析或模型就绪。
- 当前 QC 保证同一 PUE `lineage_record_id` 不跨既有 `split_group`，且同一曲线的点与派生指标由 `curve_id` 绑定；这不等于完整配方/材料族泄漏审计已经完成。
- 同一 manifest、代码和环境锁离线重建两次时，`03_规范数据/` 与 `04_派生数据/` 的快照哈希一致。

以下是后续模型就绪阶段的验收项，本版尚未宣称通过：同一论文、配方、材料族、重复试样和近重复曲线不得跨训练/验证/测试集合；代表性曲线派生值须与作者报告值做独立复核，目标相对差不超过 5%，数字化图源允许 10% 且必须标记 `digitized`。

## 3. 备选架构比较

### 方案 A：单一 Excel 宽表

优点是上手快、实验人员容易编辑；缺点是无法可靠表达一对多关系、重复试样、长曲线、多 fidelity 和许可证继承，也容易产生单位与公式漂移。仅适合作为审核界面，不作为核心数据库。

### 方案 B：SQLite 规范化关系库

优点是外键和事务完整性强、单文件便携；缺点是百万级曲线点和大批量分析导出不如列式格式方便，科研人员查看原始长表也不够直接。

### 方案 C：Parquet + DuckDB + Excel 审核层（推荐）

Parquet 适合曲线长表与高通量训练，DuckDB 可以直接跨表查询并作为可重建查询缓存，Excel 提供人工审核入口。参照完整性由 schema 校验和 SQL 测试强制执行。它比单一 Excel 稳健，又比部署数据库服务器轻量，最适合当前单机科研阶段。

```text
E:\数据\TPU\

├─ 02_暂存数据\                    # 分来源忠实抽取
├─ 03_规范数据\                    # 规范化 Parquet 表
├─ 04_派生数据\                    # 当前曲线指标与许可门控公开视图
├─ 05_数据库快照\                  # 确定性副本、快照 JSON 与 DuckDB 缓存
├─ 06_审核导出\                    # Excel 审核目录
├─ 代码\                            # 管道模块与测试
├─ 结构定义\                        # schema、枚举和单位字典
├─ 配置\                            # 来源与管道配置
├─ 清单\                            # 文件级来源 manifest
└─ 文档\                            # 设计、计划、报告和引用台账
```

每个适配器只负责“源格式 → `02_暂存数据/`”，不直接写入 `03_规范数据/`；公共规范化模块负责 `02_暂存数据/` → `03_规范数据/`。代码内部仍可使用 `staging`、`curated` 作为逻辑层标识，但项目维护的文件夹统一采用中文名称。这样修改某一个来源不会改变其他来源的处理逻辑。

本地版本库**只追踪代码、schema、manifest 和文档**，并用 `.gitignore` 排除 `01_原始数据/`、Parquet、DuckDB、审核 XLSX 及受限附件，防止约 0.60 GiB 原始数据被误提交。远程使用 [GitHub 私人仓库](https://github.com/fafasco16/TPU-HighThroughput-Screening)；私人属性不改变第三方数据许可证。

## 6. ID、单位与证据约定

### 6.1 稳定 ID

- 数据集：`ds_<来源简称>_<年份>`，例如当前的 `ds_eom_hbond_2021`。
- 文件：对规范化相对路径和 SHA-256 生成稳定 ID。
- 源内记录保留论文样品名；相关实体引入后再生成独立 `formulation_id`/`specimen_id`。
- 配方、试样与测试实体引入后，同一配方的重复、不同测试条件和循环曲线必须拥有不同 `specimen_id` 或 `test_id`，不能覆盖。

### 6.2 原始值与规范值并存

- 应力：规范为 `MPa`。
- 应变：规范为无量纲 `1`，同时保存原始 `%`。
- 温度：规范为 `K`，审核导出增加摄氏度显示列。
- 黏度：规范为 `Pa·s`。
- 时间：规范为 `s`；频率为 `Hz`。
- 韧性/滞后能密度：当应力为 MPa、应变无量纲时，规范为 `MJ·m^-3`。

任何无法可靠判断的单位标记为 `unit_status=unresolved`。v0.1 对它们产生聚合 QC 警告并阻止进入拉伸派生；许可型公开视图仍可包含原始未解析记录，因此不能被当作训练视图。正式建模前必须建立显式模型就绪门，排除 `unresolved`。

### 6.3 证据等级

- `measured_raw`：作者公开的逐点原始数据。
- `measured_summary`：作者表格中的统计值。
- `digitized`：从图中数字化；必须记录图号、工具和误差。
- `derived`：由本项目从原始曲线计算。
- `computed_dft`、`computed_md`、`predicted`：各自保持独立 fidelity。

## 8. 曲线处理与派生规则

v0.1 已实现：保留原始点顺序，不为“好看”自动平滑；对显式映射的单调拉伸曲线计算强度、断裂伸长率和曲线下面积，算法版本、积分点数和警告随派生值保存。韧性使用梯形积分：

   \[
   U_T=\int_0^{\varepsilon_b}\sigma(\varepsilon)\,\mathrm d\varepsilon
   \]

后续扩展必须遵守：单调拉伸曲线去除仪器前导空行时记录截断索引；循环曲线先按循环号或载荷方向分段，再计算加载面积、卸载面积、滞后能和残余应变；初始模量保存拟合窗口、方法和拟合优度；作者汇总值与本项目派生值并存并记录差值。原始曲线缺少试样截面积或标距时，不得把力—位移擅自转换为应力—应变。这些规则尚未全部进入 v0.1 代码与 QC。

## 9. 防泄漏与机器学习就绪性

v0.1 已实现 PUE 的 `lineage_family`、`lineage_record_id`、`split_group`，曲线点和派生指标以完整 `curve_id` 为不可拆分原子，并保留来源字段。材料/配方/试样/近重复结构级分组尚未建立，当前数据集不得直接声称完成防泄漏模型评价。

模型阶段的目标分组字段为：

- `source_group`：论文/数据集级。
- `formulation_group`：相同组分与比例级。
- `chemistry_group`：软段—二异氰酸酯—扩链剂家族级。
- `specimen_group`：重复试样级。
- `material_scope`：线性 TPU、交联 PUE/WPU、商业 TPU、复合材料、光固化弹性体等。

完成上述分组键和冻结拆分清单后，首个基线至少报告组约束随机拆分、按来源留一和按化学家族留一三种结果。论文主结论不得只引用随机拆分分数。

MatImpute 中按字段和缺失率生成的多份 PUE 文件来自同一 326 行母数据，不能计作新增样本；DQ、MatImpute、PUE-643、386 条清洗曲线和 326 条变换基准必须共享谱系/样品家族分组。任何由同一母数据派生的缺失版本都必须锁定在同一拆分侧。

## 10. 许可证与发布门控

v0.1 已逐来源登记 `license_spdx`、`derivatives_allowed`、`redistribution_allowed`、`access_restriction` 与 `status`，并将文件级 SHA-256、构建参数和这些门控元数据纳入快照身份。`commercial_use` 与正式 `attribution_text` 是对外发布前必须补齐的目标合同字段，当前不得写成已完成。

发布视图采用白名单：只有许可证明确允许演绎与再分发、且追溯字段完整的记录才进入。未知许可证默认拒绝发布；CC BY-NC-ND 数据仅存 `reference_only` 来源元数据和引用，不复制内容或可逆派生数据到发布包。

## 12. 后续子项目边界

数据库 v0.1 通过验收后再依次启动：

1. **ML 基线与适用域**：标量多任务模型、曲线表征与校准不确定度。
2. **反应约束候选生成**：固定 1–2 种软段和 1–2 种二异氰酸酯，优先搜索可购双官能扩链剂/共扩链剂。
3. **DFT/MD 多保真闭环**：只计算合成可行且信息增益高的候选，提取竞争氢键、构象、相分离与链段动力学指标。
4. **实验验证**：第一轮 8–12 个信息增益样品，第二轮 3–6 个主动学习增量；保留失败与不可加工结果。
