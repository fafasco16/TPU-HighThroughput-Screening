# TPU 数据库 v0.2 多保真设计规范

> 状态：v0.2 治理实现候选；机器 schema、枚举、质量规则及资产、来源和计算准入引擎已生成，两次真实隔离治理构建已全产物字节一致；31 表完整外键物化、科学观测迁移、动作级权利放行和快照冻结尚未完成，更未进入模型训练。
> 初版日期：2026-07-19；科学语义复算：2026-07-20
> 适用范围：`E:\数据\TPU` 数据来源登记、抽取、规范化、质量控制、许可门控、快照和审核导出。

## 1. 目标与边界

v0.2 的唯一目标是把当前原始数据仓扩展成一个可复现、可审计、可引用、可区分保真度、能够支撑后续一区论文的数据底座。数据库必须忠实表达“原料—配方—合成—试样—测试—性能—计算”关系，而不是追求一个看似庞大的宽表行数。

本阶段明确不做：

- 不训练或调参任何最终性能模型；
- 不把模拟值改写成实验值，也不提前设置训练权重；
- 不把曲线点、重复试样、同源子集或缺失值变体当成独立配方；
- 不因私人 GitHub 仓库而放宽第三方许可证；
- 不在缺少结构、配方或工艺证据时猜测原料身份；
- 不把水性 PU、交联 PUE、商业牌号、复合材料和线性 TPU 静默混成同一材料域。

### 2.2 v0.1 必须先修复的工程缺口

- 当前构建器硬编码四个来源，只从全量清单中选择这四源构建；“未注册”资产没有进入可执行的来源决策流程；
- 字段字典声明的目标表与实际输出表不一致：实际存在 `chemical_candidate`、`pue_transformed_auxiliary` 等未声明表，而 `measured_summary_transformed` 又不在现有保真度枚举中；
- 构建时主要校验清单枚举，没有对每个输出记录执行完整 schema 契约；因此“QC 0 错误”不能等价为“字段字典完全合规”；
- 现有快照主要绑定四个已选输入，转换签名未覆盖 `manifest.py`、`run_pipeline.py`、`build_catalog.mjs`，也未完整记录 Git 提交/脏状态、Python、操作系统和依赖环境；
- 现有 QC 尚未覆盖完整实体外键、子集重复、单位证据、模型用途状态和报告—快照一致性；
- 审核工作簿构建器读取 `issue_code/code`，而实际 QC 字段为 `rule_id`，会把规则错误显示成 `UNSPECIFIED`；
- 手写质量报告可能与真实快照漂移，v0.2 必须由快照生成或进行机器对账。

| 层级 | 中文目录 | 允许内容 | 禁止行为 |

| 忠实暂存层 | `02_暂存数据` | 按源表结构抽取的记录、原始单位、原始文本和表格定位 | 结构推断、单位猜测、跨来源合并 |

| 派生与视图层 | `04_派生数据` | 曲线指标、结构标准化结果、PURT 子集视图、质量评分 | 将子集重复计入母集；修改原始标签 |

每条记录必须保留 `source_id + source_file_id + source_locator`。任何人工修订必须形成新记录或修订事件，不能静默覆盖来源值。

## 4. 来源准入优先级

### 4.1 P0：全量资产先登记，再决定是否解析

由冻结 `discovery_scope + excluded_path_rules` 动态发现的全部资产必须获得明确角色：`primary_data`、`supplementary_information`、`code`、`simulation_input`、`simulation_output`、`computed_property_output`、`model_artifact`、`model_output`、`derived_duplicate`、`mirror_duplicate`、`subset_view`、`documentation`、`restricted_reference` 或 `excluded_non_domain`。验收条件是发现集合与“已登记或有证据排除”集合的双向差集均为零，而不是永久等于 1,606。

“已登记”不等于“可训练”。本规范存在两组性质不同的六维，必须使用不同名称：

1. **治理生命周期六状态**：`registration_status`、`availability_status`、`parse_status`、`scientific_admission_status`、`model_readiness_status`、`release_status`，描述资产或记录在工作流中走到哪一步，字段统一以 `_status` 结尾；
2. **观测语义六维**：`origin_kind`、`reduction_level`、`acquisition_method`、`evidence_quality`、`scientific_use_class`、`rights_evidence_state`，描述一条观测本身是什么。

两组字段不得互相推导或替代。例如 `parse_status=parsed` 不意味着科学准入，`scientific_use_class=primary_experimental` 也不意味着允许公开发布。

## 5. v0.2 核心实体与契约边界

### 5.1 来源、定位、血缘与权利

`source_scope` 是来源独立性、计数和权利范围的共同边界。论文 DOI、数据 DOI、deposit、版本、文件和逻辑表分别建 scope；`supplement_to/companion_to/subset_of/supersedes/mirror_of/derived_from/same_study_as` 必须有证据。companion、supplement 或同一实验批次的多个 deposit 默认属于同一 `source_family`，只有证明独立材料制备或独立实验后才可计作独立来源。

`rights_evidence_package` 至少保存 canonical/resolved URL、retrieval method、HTTP status、retrieved at、ETag/Last-Modified、media type/charset、字节数、正文归档路径和 SHA-256、响应头、定位、适用对象/版本、原始/规范许可证表达式、条款 URL、访问/撤回状态、采集者/核验者、冲突组和 supersedes。证据类型至少覆盖 repository metadata、publisher page、license text、terms of use、API response、file manifest、author communication、access restriction 和 withdrawal notice；authority type 区分官方仓库、出版商、许可人、作者授权、Crossref 与第三方摘要。未归档正文的会话哈希最多为 `captured_unverified`。

`rights_fact` 的 predicate 至少覆盖 declared license、commercial use、derivative、redistribution、TDM、AI training、attribution、access restriction 和 withdrawn。证据未声明的项目写 `unspecified`；Crossref 缺 license 字段只构成 evidence missing/scope unresolved，只有同一对象、版本、范围的明确声明无法同时满足时才登记 conflict。

### 5.2 可执行 schema 与稳定身份契约

设计规范冻结的是以下不可变约束；随后创建并经审阅冻结的 v0.2 YAML/JSON Schema 才是机器执行的唯一合同：

- 每张表必须声明完整字段集合、Arrow/DuckDB 类型、nullability、枚举、PK、FK、基数、自然唯一键、条件必填、CHECK 约束和修订策略；
- 暂存、规范、派生、发布和审核输出不得出现 schema 外表或 schema 外字段；
- 所有 FK 从 schema 元数据自动遍历验证，不允许继续手写少数关系；
- `record_uid` 由 `UUIDv5(namespace[entity_type,id_algorithm_version], canonical_identity_key)` 生成，同时保存完整 identity-key SHA-256 做碰撞检查；不得包含 snapshot、绝对路径、下载日期、显示名或不稳定行号；
- 有稳定来源主键时 identity key 使用 `source_scope + source_record_identifier`；否则使用版本化规范自然键。科学身份改变时生成新 UID，并用 `supersedes/equivalent_to/migration_map` 关联，不静默复用；
- `record_revision` 承载 schema/content 变化，`snapshot_record` 选择修订；同一 `record_uid` 在一个快照中只能选择一个修订；
- `supersedes` 与 `migration_map` 保存 v0.1→v0.2 及后续 schema 迁移，禁止静默重写历史 ID；
- 每张表具有 `planned/implemented/populated/qc_passed/frozen` 状态、schema hash、行数和输出哈希；
- 字段字典、枚举、Parquet Arrow schema、DuckDB schema、审核工作簿和报告进行机器对账。

科学主链禁止使用未约束的 `target_table + target_id` 或文字中的“指向 A 或 B”。跨实体治理表可以引用 `record_registry.record_uid` 并校验 `expected_entity_type`；科学关系必须使用显式超类型或具名关联表。确实需要多个候选 FK 时，必须具有数据库 CHECK 与全量 QC 双重 XOR 约束。

### 5.3 实验、加工、重复与失败结果链

```text
chemical ─ material_lot ─ formulation_component ─ formulation
                                                       │
                                                       └ synthesis_batch ─ synthesis_outcome
                                                                 │
                                                                 └ polymer_material ─ material_state
                                                                                         │
                                                                         processing_event chain
                                                                                         │
                                                                                      specimen
                                                                                         │
                                                                                  measurement_run
                                                                                   ├ observation
                                                                                   └ measured_curve ─ sequence/point/value

replicate_group ─ aggregate_observation
observation_subject_registry ─ typed subject extension
event_registry ─ synthesis/processing/measurement/computation ─ failure_event
```

关键规则：

- `chemical` 表示可确认的离散化学实体、混合物或分布型聚合物原料；供应商牌号、盐/溶剂化物、立体/互变异构与结构标准化结果分开保存；
- `material_lot` 保存供应商、批号、纯度、水分、Mn/Mw/PDI、羟值、NCO 含量及其测量证据；
- `formulation` 是确定配方；`formulation_component` 保存角色、原始量、单位、质量/摩尔/当量表示、证据和配方闭合状态；
- `synthesis_batch` 保存加料顺序、一步/预聚体法、催化剂、溶剂、温度、时间、气氛、转化、脱泡、成膜/成型与后处理；
- `synthesis_outcome` 只描述合成批次：`target_material_obtained/material_obtained_off_spec/low_conversion/gelation/phase_separation/no_material_obtained/outcome_unknown`；不能承载加工失败、测试失败、计算失败或低性能判断；
- `polymer_material` 表示合成所得材料身份；`material_state` 表示热史、形貌、含水和老化状态；`processing_event` 以有序事件链记录浇注、挤出、打印、固化、退火、调湿和循环历史；
- `event_registry` 统一登记事件状态，`failure_event` 保存失败阶段、模式、严重度、可恢复性和定位；测试失败保留 measurement run 但不生成伪数值，计算未收敛不计计算观测；低性能是有效观测，由版本化候选阈值裁决，不是失败事件；
- `measurement_run` 是一次实际测试；`replicate_group` 保存成员，`aggregate_observation` 保存 `aggregate_origin`、`membership_completeness`、`n_reported/n_total/n_used/n_basis`、SD/SE/CI/range、聚合方法和父观测；
- 作者仅报告均值和 n 时允许 `membership_completeness=unavailable`，禁止虚构成员；只有 `complete` 才要求成员数与 n 对账。项目汇总必须有成员，并与作者汇总分成不同记录；
- `observation_subject_registry` 通过受约束子类型表达 batch/material/state/specimen/measurement run/replicate group；标量不再一律强制绑定单一 `test_id`；
- 由曲线计算的指标进入项目派生观测，并保存算法、参数、输入点集合和版本，不覆盖作者报告值。

### 5.4 计算与模拟实体链

| 表 | 主键 | 必需内容 |
|---|---|---|
| `computational_system` | `computational_system_id` | 片段/重复单元/低聚物/多链/周期体系、组成、链长、原子数、构型和盒信息；不强制存在实验配方 |
| `method_model` | `method_model_id` | DFT/MD/粗粒化/GC/ML/本构方法、软件与版本、参数来源、适用域和引用 |
| `computational_activity` | `activity_id` | activity kind、系统、方法、输入/输出哈希、参数、随机种子、资源、状态、收敛与质量标志 |
| `computed_observation` | `computed_observation_id` | 性质定义、原始/规范值和单位、不确定度、聚合层级、条件及父活动 |
| `computational_artifact` | `artifact_id` | 输入脚本、结构、轨迹、日志、检查点、模型和派生文件的角色及哈希 |
| `system_mapping` | `mapping_id` | 计算体系到 chemical/formulation/material 的可选映射、断言类型、置信度和证据 |

DFT 至少记录泛函、基组、色散修正、电荷/多重度、溶剂模型和收敛阈值；MD 至少记录力场、参数来源、电荷方法、系综、时间步长、平衡/生产时长、温压、冷却/加载速率、链长和独立重复。GC 与 ML 预测属于 `computational_activity`，但不得伪装成有轨迹/收敛过程的 `simulation_run`。只有存在输出、方法完整并通过相应质量门的活动才能产生科学就绪观测。

### 5.5 实验与计算序列超类型

应力—应变、松弛、DMA 扫描、本构拟合和低维计算时间序列共用 `sequence/sequence_channel/sequence_point/sequence_value`，但实验和计算子类型必须分开：

- `measured_curve(sequence_id, observation_subject_id, measurement_run_id, curve_role)` 只承载真实测量序列；
- `computed_curve(sequence_id, computational_system_id, computational_activity_id, curve_role)` 的角色限定为 `direct_output/postprocessed/constitutive_fit/surrogate_prediction`；
- 图像数字化只改变 `acquisition_method=figure_digitization`；若图中来源是实验，`origin_kind` 仍为 `experimental`；
- 本构拟合保存校准数据 scope、参数和残差，不能冒充直接模拟；MD 全原子轨迹保留为 artifact，只有明确抽取的低维序列进入 sequence；
- `observation_sequence` 将韧性、滞后、断裂点等标量派生观测与输入序列相连。

每个 sequence 保存 kind、origin、reduction、acquisition、条件集、点数和内容哈希；每个 channel 保存 independent/dependent/auxiliary 角色、quantity definition、原始/规范单位。点索引、segment、cycle 和多通道值不得压入不可审计的 JSON 字符串。

### 5.6 可合成性、应用与新颖性实体

为满足“真实合成、有应用前景、未被充分研究”的最终目标，数据库必须承载而非仅在文字中提到：

- `hazard_assessment`：物质/配方级 GHS、暴露、监管、EHS 来源和评估日期；
- `supplier_offer`、`cost_observation`、`availability_observation`：供应商、地区、币种、规格、价格、MOQ、交期、有效日期和证据；
- `synthesis_feasibility`：官能度、凝胶风险、NCO/OH、理论 Mn、原料水分、黏度/加工窗口和规则版本；
- `novelty_search`、`novelty_hit`：论文、专利、供应商技术资料、结构/配比/用途检索式、数据库、日期、相似度与人工裁决；
- `candidate_decision`：硬门、Pareto 目标、阻断原因、证据快照和审阅结论。

这些信息具有时间和地区依赖性，不能作为 chemical 的永恒属性，也不能在检索前生成“无人研究”结论。

### 5.7 线性 TPU 材料域的操作定义

不得仅凭论文标题、文件名、作者使用“TPU”一词或存在 NCO/OH 字段将材料归入主域。必须分别保存：

| 字段 | 枚举 | 含义 |
|---|---|---|
| `backbone_class` | `polyurethane/polyurethane_urea/other/unknown` | 主链化学类别 |
| `network_architecture` | `nominal_linear/linear_supported/branched/covalently_crosslinked/unknown` | 分子架构与永久网络证据 |
| `thermoplastic_evidence` | `none/author_asserted/process_supported/reprocessability_supported/contradicted` | 热塑性证据强度 |
| `material_domain_assertion` | `linear_tpu_primary/linear_pu_candidate/external_pu_domain/blocked` | 本项目材料域裁决 |

`nominal_linear` 至少要求所有有意参与链增长的异氰酸酯、聚合物二元醇和扩链剂为二官能，官能度和计量有证据，未报告三官能及以上交联剂、永久网络形成剂或后交联步骤，且不存在凝胶、不可溶永久网络或不可逆固化反证。`linear_supported` 还需可溶性/凝胶分数、可解释分子量分布、可逆加工等至少一类独立证据；Carothers 估算不能单独证明线性。

`process_supported` 至少需要熔融加工、挤出、热压、注塑、打印或可逆软化—再成型证据；仅溶液浇膜不等于已证明热塑性。只有 backbone、架构、热塑性和配方—批次—材料状态血缘同时通过的记录进入 `linear_tpu_primary`。交联 PUE、WPU、泡沫、复合材料、商业未知配方和特殊超分子体系保持独立域；未知不得自动解释为线性 TPU。

### 5.8 独立配方身份与容差合同

必须同时保留：

- `source_formulation_id`：来源作者给出的样品/配方身份；
- `independent_formulation_uid`：跨来源、与论文和批次无关的精确名义配方身份；
- `formulation_equivalence_group`：按版本化科学容差形成的近等价候选组。

精确配方签名至少包含每个组分的化学身份、角色、官能度、异构/盐/混合物状态，分布型原料家族、端基、Mn/Mw/PDI 或牌号，质量/摩尔/官能团当量组成，NCO/OH、硬段定义和含量，以及催化剂、填料、增塑剂、溶剂、交联剂和功能添加剂的存在/用量。合成路线、加工、热史和测试条件不进入配方键，而分别属于 batch/event/state/measurement；同配方不同批次不得增加独立配方数。

数值解析容差只消除单位、浮点和有效数字差异；科学近等价容差只能生成候选组，不能合并精确 UID。`equivalence_policy` 保存字段、材料域、比较基准、绝对/相对容差、来源分辨率、不确定度、依据、批准者和快照。组分有无、官能度、线性/交联、化学家族、异构体、牌号/Mn 无法证明等价、功能添加剂、未知与零值等差异不得被通用百分比吞并。关键身份未知时只生成来源内 provisional 身份。

## 6. 统一观测、性质与单位语义

### 6.1 观测语义六维

不再使用一个混合的 `fidelity` 字段同时表达来源、汇总、提取方式和权利。每条观测至少保存：

| 轴 | 示例枚举 | 回答的问题 |
|---|---|---|
| `origin_kind` | `experimental/dft/md/coarse_grained_md/group_contribution/ml_prediction` | 数值由什么科学过程产生；候选身份另存，不能冒充数值来源 |
| `reduction_level` | `raw_point/measurement/replicate/aggregate/derived` | 数据经过何种汇总或推导 |
| `acquisition_method` | `direct_table/structured_workbook/repository_file/pdf_table/docx_table/figure_digitization/author_communication/project_recalculation` | 数据怎样进入项目 |
| `evidence_quality` | `Q1/Q2/Q3/Q4/Q5` | 来源定位与语义证据有多可靠 |
| `scientific_use_class` | `primary_experimental/primary_computational/auxiliary/representation/validation/audit_only/blocked` | 在明确 use scope 下允许进入哪类科学视图 |
| `rights_evidence_state` | `unreviewed/evidence_missing/captured_unverified/scope_unresolved/conflict_detected/verified/stale/withdrawn` | 权利证据是否完整、适用和有效；不直接回答能否执行动作 |

材料域、观测主体、性质定义和测试条件另列，不从上述维度推断。`scientific_use_class` 通过 `scientific_use_assignment(record_uid,use_scope_id,class,rule_id,snapshot_id)` 相对于明确任务保存，不能成为脱离用途的永久全局标签。任何动作是否允许只由 `rights_action_decision` 决定；界面可生成带动作配置且自动失效的 `rights_summary`，但它不是准入真值源。

### 6.2 缺失值是字段级事实

`missing_value(record_uid, field_name)` 必须对关键字段逐项记录：`not_reported`、`not_measured`、`not_applicable`、`unknown_identity`、`below_detection`、`withheld`、`parse_failed` 或 `pending_manual_review`，并关联证据和复审状态。

每个关键字段满足 XOR 约束：字段有值时不得同时存在缺失行；字段为空时必须且只能有一条缺失原因。不得把空字符串、`0`、`N/A`、未知身份和不适用混为同一状态。

### 6.3 性质定义、统计量与可比性

`property_definition` 至少包含 `property_code`、量纲、规范单位、允许测试类型、物理定义、范围规则、是否允许负值、聚合规则和版本。第一批必须明确区分：

- Young、tangent、secant、storage、loss modulus；
- nominal/engineering 与 true stress，engineering/logarithmic/true strain；
- Tg 的 DSC/DMA/其他方法及 onset/midpoint/inflection/peak 定义；
- 拉伸/屈服/断裂强度与对应事件；
- 韧性、滞后能和循环耗散的积分边界与基线；
- 自修复效率基于强度、伸长、韧性还是其他指标，以及时间、温度、压力、切割/接触条件；
- GPC Mn/Mw/PDI 的方法、校准标准和批次主体。

标量观测必须保存 `value_origin=author_reported/project_derived/digitized`、`uncertainty_value`、`uncertainty_type=SD/SE/CI/range`、置信水平和父观测。汇总记录另存 `aggregate_origin=source_reported/project_computed`、`membership_completeness=complete/partial/unavailable/not_applicable`、`n_reported/n_total/n_used/n_basis`、聚合方法及成员纳入/排除/权重。作者未给逐样本成员时忠实保存 `n_reported`，不得虚构成员；只有 complete 时要求 n 与成员数相等。只有性质定义、主体和条件兼容的记录才允许合并比较。

### 6.4 单位定义与转换证据

| 性质 | 第一批规范单位 |
|---|---|
| 强度及各类模量 | MPa |
| 伸长、残余应变、恢复率、自修复效率 | 无量纲 fraction，展示时可转 `%` |
| 韧性、滞后能、循环耗散 | MJ/m³ |
| Tg、Tm、测试温度 | K |
| 密度 | kg/m³ |
| 黏度 | Pa·s |
| 应变率 | s⁻¹ |
| 频率 | Hz；角频率另存 rad/s，不静默互换 |
| 分子量 | g/mol |
| DFT 能量 | kJ/mol，同时保留原始 Hartree/eV |

`unit_definition` 使用可解析单位代码（优先 UCUM）、量纲、比例/偏移和别名状态；`unit_evidence` 保存字段、原文单位、定位和置信度；`unit_conversion_event` 保存原值、规范值、规则版本和往返容差。源单位证据不足时只保留原值并标记 `unresolved`，不得进入主科学就绪视图。

### 6.5 后续训练权重的边界

训练权重不能写回或篡改数据库事实。v0.2 不预设 `1.0/0.5/0.2` 一类任意权重；后续方案只能基于观测语义、材料域、不确定度和完整条件，通过分组防泄漏、来源外验证与消融实验确定。模拟值可以入库，但计算输入不能冒充结果，缺少协议/输出/质量证据的数值只能停留在审计或表示层。

### 6.6 样本瀑布与多目标交集

每个冻结快照生成可机器复算的瀑布：发现资产 → 来源文件 → 来源记录 → 成功解析候选配方 → 身份可解析 → 目标材料域 → 精确独立配方 → 合成批次 → 材料状态 → 测量运行 → 兼容主观测 → 各目标独立实验主体 → 多目标严格交集 → 满足应用硬要求且证据完整的主体。相邻层差值必须由 reason code 完全解释，并与审核簿对账。

对目标集合 T 分别报告：

- `target_union_count`：至少一个目标有实验观测的独立配方数；
- `target_pattern_count`：每一种目标具备/缺失模式的独立配方数；
- `strict_joint_count(T)`：全部目标来自同一批次和兼容材料状态，可由同批兄弟试样测得；
- `formulation_linked_joint_count(T)`：同一精确配方但跨批次、跨状态或跨来源；
- `predicted_completion_count(T)`：至少一个目标由 ML/GC/DFT/MD 补全。

只有 strict joint 可作为实验多目标 Pareto 主计数；formulation-linked 只用于辅助/敏感性分析，predicted completion 永远不能冒充观测交集。重复试样、作者汇总、曲线点、数字化/派生指标、模拟帧和插补版本均不得增加独立配方数。

### 6.7 应用需求向量

数据库不得使用脱离用途的单一“综合性能”或“高性能”标签。每个方向建立版本化 `application_profile + application_requirement`，每个需求保存 property、主体、单位、标准、温湿度、速率/频率/循环、老化和试样条件，`minimize/maximize/target/range`，硬/软约束、阈值与不确定度、基准材料、地区、有效日期、引用和批准状态。

应用向量按需覆盖强度、伸长、模量、韧性、Tg/服役温区、撕裂/耐磨、循环滞后、压缩永久变形、阻尼、疲劳、耐水解/耐候、加工黏度与温区、再加工性、EHS、供应、成本及失效模式。权重和标量化属于 `decision_scenario`，不是材料属性；优先保留单目标值、硬约束状态和 Pareto 关系。缺失要求为 unknown，不能自动视为通过或失败。

## 7. 证据、科学就绪与权利分级

### 7.1 证据质量只评价证据，不评价来源类型

| 等级 | 定义 |
|---|---|
| Q1 | 作者原始机器可读记录，定位、身份、单位、条件与统计语义完整 |
| Q2 | 作者机器可读记录，但部分配方、工艺、条件或统计语义缺失 |
| Q3 | PDF/DOCX 表格经两个独立流程核验并完成差异裁决 |
| Q4 | 图像数字化并保存像素、轴、校准和误差证据 |
| Q5 | 来源、定位、单位、身份或语义存在未解决冲突，仅审计 |

实验、DFT、MD、GC 和 ML 都可以获得 Q1–Q5 中相应等级；计算来源不再自动等于“低证据”。物理保真度由 `origin_kind + method_model + conditions` 表达。

### 7.2 科学就绪状态（只登记，不训练）

- `primary_experimental`：实验观测在明确 use scope 下通过配方/材料身份、性质、单位、主体、条件、血缘和重复语义门；
- `primary_computational`：实际 DFT/MD/粗粒化输出具有完整协议、输入输出血缘、质量/收敛检查、适用域和必要重复/不确定度；只能作为计算/机理/代理任务主标签，不能验证真实材料性能或可合成性；
- `auxiliary`：科学可靠但缺少部分关键条件，或只适合辅助任务；
- `representation`：只有结构、计算输入、候选或无目标表征；
- `validation`：材料身份不完整但适合曲线/工况/本构外部验证；
- `audit_only`：有研究价值但尚不能进入分析视图；
- `blocked`：科学语义或质量存在阻断问题。

GC 和 ML 输出原则上只能是 auxiliary/representation；若后续任务需将经外部验证的代理作为主目标，必须建立新的 use scope、独立规则和消融验证。实验主观测与计算主观测在计数、覆盖、抽样和论文表述中始终分开。

### 7.3 权利层独立于科学就绪

权利对象统一为 `metadata/raw/normalized/derived/aggregate/model`；`adapted`、`project_derived` 统一映射为 derived。科学维度的 `reduction_level=aggregate/derived` 与权利对象类别不得混用，normalized/aggregate 也不能因“不是原文件”自动视为可公开。

每个裁决精确绑定：

```text
operation = retrieve/store/parse/transform/analyze/train/evaluate/redistribute/publish/deploy
actor = project_member/institution_member/approved_collaborator/external_processor/public/commercial_partner
purpose = evidence_audit/noncommercial_research/teaching/public_benchmark/commercial_research/product_service
rights_object_class = metadata/raw/normalized/derived/aggregate/model
context_profile = access control + hosting + jurisdiction + retention + processor
```

裁决为 `allow/allow_with_obligations/deny/manual_review`；自动合并优先级为 `deny > manual_review > allow_with_obligations > allow`，义务取并集。`manual_review` 在自动门中等同阻断，但不伪装成已证明法律禁止。常用 reason code 至少包括 `EVIDENCE_MISSING/SCOPE_UNRESOLVED/LICENSE_CONFLICT/TDM_AI_UNSPECIFIED/NC_PURPOSE_MISMATCH/ND_DERIVATIVE_SHARE/ACCESS_WITHDRAWN/AUTHOR_PERMISSION_REQUIRED/LINEAGE_INCOMPLETE/OBLIGATION_UNSATISFIED/EXPLICIT_PROHIBITION`。

训练权、模型发布权和部署权分别裁决；允许 train 不等于允许 publish/deploy model。私人 GitHub、外部 OCR、云训练和第三方 API 均按 external processor 重新裁决。ND 区分内部制作派生与公开分享派生；NC 保留主体/目的；任何祖先证据或血缘缺失时不得自动 allow。

### 7.4 状态必须由规则生成

治理生命周期六状态分别保存并使用冻结枚举：

- registration：`discovered/registered/excluded_with_evidence`；
- availability：`available/metadata_only/request_required/unreachable/withdrawn`；
- parse：`not_attempted/parsed/partially_parsed/failed/not_applicable`；
- scientific admission：`pending/admitted/admitted_with_waiver/rejected`；
- model readiness：`not_assessed/eligible/held_out_only/ineligible/blocked`；
- release：`not_assessed/approved/denied/expired/superseded`。

`scientific_use_assignment` 与 `rights_action_decision` 由冻结规则重算，人工只提交证据、裁决或 waiver，不能直接把记录改成“可用/可发布”。状态迁移记录旧值、新值、触发规则、证据、审阅者和时间。

治理角色至少包括 source curator、data steward、schema owner、domain reviewer、methods reviewer、rights reviewer、QC owner、release manager、snapshot approver 和 independent auditor。每项人工决定保存 actor、role、decision type/value、reason code、证据、规则版本、时间和有效期。例外、公开发布和快照冻结实行提出者与批准者分离；人员不足导致角色冲突时必须记录，并在论文/公开发布前独立复核。blocking issue 不得通过 waiver 变成冻结通过；其他 waiver 必须限定范围、补偿控制、责任人、到期和复审状态。

### 7.5 候选声明的四条独立证据轴

“高性能”“可合成”“有应用前景”和“新颖”独立评估。每条声明保存 `evidence_level + pass/fail/inconclusive + evidence_ids + scope + assessed_at + assessor + rule_version`；高证据可支持失败结论，证据强度不能与结论是否有利混为一体。

| 轴 | 0级 | 1级 | 2级 | 3级 | 4级 |
|---|---|---|---|---|---|
| performance | 无可用证据 | 仅预测/模拟或数据集相对排名 | 单批兼容实验与明确基准比较 | ≥3 个独立批次覆盖应用硬要求并报告不确定度 | 独立实验室/标准化或服役老化后仍满足 |
| synthesis | 未评估 | 规则可行性 | 完整路线、相近先例、EHS/加工窗口，候选尚未合成 | 至少一批真实合成且身份/产率/过程/失败完整 | ≥3 批复现及放大/稳健性证据 |
| application | 泛化用途或未评估 | 映射到版本化应用向量 | 兼容标准下全部硬门和基准比较 | 原型/循环/老化/关键失效验证 | 独立场景或行业标准验证 |
| novelty | 未检索 | 名称/精确结构基础检索 | 文献+专利多库检索，覆盖同义词、组分、结构、配比、用途 | 最近似命中全文/权利要求裁决和差异矩阵 | 提交前独立复核并更新检索日期 |

数据集分位数只能产生 `dataset_relative_rank`，不能替代应用基准。禁止永久写“从未有人研究”；只允许：“截至某日期，在所列数据库、检索式和人工审阅范围内，未发现满足预设相似性条件的先前公开体系。”该结论随日期失效，也不是专利法律意见。

### 7.6 multi-fidelity、multimodal 与 cross-scale 边界

- `multi_fidelity`：同一或经明确映射的科学量，由不同近似层级、分辨率、精度或成本获得；每个 `fidelity_family` 局部声明 QoI、参考层、体系/条件映射、方法、误差/校准、成本和不确定度传播；
- `multimodal`：同一实体的结构、标量、曲线、光谱、图像、文本或工艺序列；
- `cross_scale`：电子—原子—链段—介观—材料—试样—应用尺度的机制或代理关系；
- `multi_task`：同一主体多个不同性质；`multi_source`：不同论文、仓库或实验室。

DFT 氢键能与实验韧性、未经验证映射的短链 MD 拉伸与宏观准静态拉伸属于 cross-scale；化学图+曲线+SEM 属于 multimodal；ML 预测与其训练标签不是独立低保真真值。不同体系、不同物理量的 DFT/MD/实验拼接不得泛称 multi-fidelity。任何后续保真度编码或融合权重都是版本化派生视图，不能覆盖观测事实。

## 8. 强制质量门

### 8.1 动态资产、来源与时间证据门

- 扫描范围、忽略规则、符号链接/嵌套仓库策略和扫描器版本进入快照；发现集合与 `source_file + asset_decision/exclusion_record` 集合双向 anti-join 必须为零；
- 每个文件保存大小、SHA-256、媒体类型、来源、资产角色和时间证据；`retrieved_at`、`first_observed_at` 与未知原因分开，不能把统一盘点日期冒充下载时间；
- 同哈希镜像、子集、扩展版、缺失/插补版、特征变换和论文/数据 companion 关系均机器可查；
- 论文声称规模、仓库元数据规模、实际文件规模、抽取记录数和最终唯一实体数分别报告，并保存 `count_evidence`；
- `publisher_claim/repository_metadata/temporary_file_audit` 不能升级为冻结事实；只有绑定文件 SHA-256、解析器、过滤/去重规则和快照的 `ingested_file_recount` 可进入数据库规模主张；
- 正式 citation key、论文 DOI、数据 DOI、仓库 commit、访问日期和许可证据可机器读取。

### 8.2 化学、配方、实验与统计语义门

- 结构标准化保存原始结构、规范化规则版本、盐/混合物/立体化学状态和标准化失败原因；不得用 canonical SMILES 抹去有意义差异；
- 配方组件质量/摩尔/当量表示一致，规定允许误差并生成配方闭合结果；未闭合不得自动推断；
- 主实验观测可回连 formulation、batch、polymer material/state、正确 observation subject、property definition、条件、单位和血缘；
- 重复测量、作者汇总和项目派生分层；`n_reported/n_used/n_basis`、成员完整性、SD/SE/CI、父观测和聚合方法一致；
- 合成、加工、测量和计算失败按事件阶段保存；低性能作为有效观测及候选裁决保存，避免成功偏倚；
- 线性 TPU、交联 PUE、WPU、商业 TPU、复合材料、泡沫和通用聚合物分域；跨域使用必须显式声明任务；
- 每个主路线材料完成 backbone × network architecture × thermoplastic evidence × material domain 裁决；未知不得进入线性 TPU 主域；
- 精确配方 UID 与 near-equivalence 分开；科学容差只生成候选组，跨源合并具有字段级比较证据和版本化策略；
- 自修复效率、Tg、模量、应力/应变、韧性和 GPC 指标通过性质定义兼容门后才能合并。

### 8.3 计算与模拟语义门

- 计算输入、工作流、实际输出、聚合结果和 ML 预测分别保存；没有输出的 ADEPT 输入不能计作模拟数据；
- DFT/MD 活动缺程序/版本/方法/条件/输出/收敛状态时不得生成 `primary_computational/auxiliary` 计算观测；
- PolyOmics PURT 和其他筛选子集只作为母集可重建视图；
- 相同体系在 DFT、MD、GC、ML 和实验中的观测分别保存，不覆盖；
- 项目重算与第三方原计算分开，保存输入、输出、参数、随机种子和方法模型哈希；
- `system_mapping` 缺证据时保留为低置信断言，不把重复单元自动等同于真实配方。

### 8.4 等价、重复与防泄漏门

建立 `equivalence_group + equivalence_membership`，`group_type` 至少覆盖：`exact_file_hash`、`parent_dataset`、`publication`、`source_record`、`chemical_structure`、`formulation`、`synthesis_batch`、`specimen_replicate`、`curve`、`lineage_family` 和 `computational_system`。

- ACS 扩展集与旧 43 条只有在逐行匹配证明后才共享 subset/parent group；PURT 与 general、MatImpute/DQ PUE、原始/汇总/数字化/派生版本必须共享已证明的相应父组；
- 同一配方在不同论文、同一材料的多个命名通过精确身份键或版本化 near-equivalence 候选 + 人工裁决形成跨源组；科学容差不得自动合并精确配方；
- 同一曲线及派生指标、同一批次/重复样、子集/插补/变换版、关联计算不得跨受保护分区；
- 外部验证源不得与开发源共享 `parent_dataset/publication/source_record/formulation` 等保护组；
- v0.2 只冻结 equivalence/protected group，不预设训练/验证比例或随机种子；`partition_assignment` 属于后续明确任务/快照。若 v0.2 提供参考分区，必须声明 use scope、保护组、算法和种子，并验证零跨组；没有适用泄漏组的记录不得标记任务就绪。

### 8.5 曲线门

- 曲线轴单独保存 quantity、原始/规范单位、工程/真实定义和单位证据；
- 点数、索引连续性、排序、重复点、非有限值、加载阶段和 cycle 可审计；单调、循环、压缩、松弛和 DMA 使用不同规则；
- 积分、峰值、断裂点、滞后与恢复指标保存算法、基线、参数、输入点哈希、警告和可复算结果；
- 曲线点永远不计入独立材料/配方数；一条 500 点曲线仍是一个测量序列。

### 8.6 动作级权利与发布门

- 权利闭包覆盖全部贡献来源，不选择最宽松许可证；元数据冲突、未知、ND、NC、TDM/AI 不明确、撤回和作者申请均按动作 fail closed；
- metadata、raw、normalized、derived、aggregate、model 分别裁决；ND 原样分享、内部制作派生与公开派生发布不能混为一谈；
- CC BY/CC BY-NC 的署名、许可链接、修改说明和非商业限制进入发布清单；
- 对不能再分发的来源，只发布允许的元数据、固定入口、哈希、处理代码和经裁决允许的统计；
- 每个发布视图由冻结策略重算，并能列出阻断记录、贡献来源和 reason code。
- 只有 URL、状态码和响应哈希而没有归档正文/响应头的在线核验最多为 `captured_unverified`；任何 allow/allow-with-obligations 必须可达已归档并经核验的 evidence package；
- 每个公开 artifact 自动生成 citation、署名、许可证链接、修改说明及其他义务；证据冲突、撤回、版本替换或条款变化会使旧裁决失效。

### 8.7 机器规则目录与问题处置门

`quality_rule` 至少保存 `rule_id/version/scope/default_severity/blocking_profiles/implementation_hash`。规则族必须覆盖：

- schema 表/字段/类型/null/枚举；PK、FK、基数与唯一约束；
- 原始可达血缘、定位完整、字段级缺失 XOR；
- 单位量纲、证据、转换往返；性质—测试兼容和范围；
- 文件重复、子集、跨源等价与泄漏组；配方闭合；
- 曲线轴、点数、索引、派生复算；
- 计算协议、输出和收敛；
- 传递许可、视图资格、快照、报告和仓库第三方原始数据扫描。

`quality_issue` 保存 snapshot、rule version、blocking scope、record/field、observed/expected JSON、证据、owner、status、resolution 和 waiver。waiver 必须有批准者、理由、范围和失效条件；blocking issue 不可豁免为冻结通过。审核工作簿必须原样保留 `rule_id`，禁止 `UNSPECIFIED`。

### 8.8 快照、环境、重建与报告门

- 快照分别绑定动态全量资产清单和本次解析输入，保存逻辑内容哈希、文件字节哈希、行数、Arrow schema 指纹和扫描规则；
- 转换签名覆盖全部适配器、`manifest.py`、`run_pipeline.py`、`build_catalog.mjs`、schema、枚举、来源配置、依赖锁、规则集和算法参数；
- 保存 Git commit、dirty 状态及 diff hash、Python 实现/版本、OS/架构、locale、timezone 和依赖锁哈希；
- 两次重建使用两个干净隔离输出目录；逻辑表内容必须一致，Parquet 字节哈希作为同环境附加证据而非跨环境唯一标准；
- `dataset_snapshot/snapshot_input/snapshot_output/snapshot_environment/snapshot_report/table_build_status` 分离；
- 质量报告、数据集卡、审核簿、引用台账、许可清单和排除清单绑定同一 snapshot 并生成机器对账报告；
- 失败构建只生成 provisional 证据，不得覆盖最近冻结快照。

逻辑哈希使用版本化规范编码：列按冻结 schema 顺序，行按稳定主键排序；字符串 UTF-8/NFC，时间统一 UTC 和冻结精度，decimal 固定 scale，binary 使用 base64；浮点按 IEEE-754 位模式并冻结 NaN/-0.0 规则；null、NaN、无穷和 missing reason 使用不同类型标记；list 保序、map 按 key 排序。计算 `row_hash=SHA256(canonical_typed_row)`、`table_logical_hash=SHA256(schema_hash || ordered_row_hashes)`、`snapshot_logical_hash=SHA256(sorted(table_name,row_count,table_hash))`。来源文件哈希、输出字节哈希和逻辑哈希分别保存。

### 8.9 科学覆盖、偏差与声明范围门

- 生成 `material_domain × property_definition × test_condition × origin_kind × source_family` 覆盖矩阵，以精确独立配方、批次和严格多目标交集为主要分母，同时报告记录/观测数、独立材料/出版物/实验室数和关键字段完整率；
- `primary_experimental/primary_computational` 的身份、主体/体系、性质、单位、关键条件、血缘和泄漏组完整率必须为 100%；辅助层缺失必须有字段级原因；
- 任何拟声称跨来源泛化的目标至少 3 个独立 source family 且需要完全隔离的来源外证据；“3 个来源”和“最大来源 80%”只是最低必要/审计启发式，不是通用性充分条件；不足时数据库仍可冻结，但 claim 自动收缩；
- 报告每个目标的最大来源、论文和化学家族占比，并按独立配方/批次而非曲线点计算；单源超过 80% 标记 `source_dominated` 警告并要求来源外验证或收缩声明；
- 比较跨源性能前必须通过 property/test compatibility；不兼容数据保留但分层报告；
- 失败/不可行/低性能记录的获得与缺失、出版偏倚、许可可得性偏倚和纳入选择偏倚定量披露；比较纳入与排除组的化学/性能/年代分布；
- 披露实验室/仪器/操作者、测试方法、温度/速率、年代、非随机缺失、模拟力场和数字化误差偏差；
- 化学组成、软/硬段家族、硬段比例、NCO/OH、Mn、添加剂、材料域、合成/加工、温度/速率和应用要求覆盖均输出分布，不用总行数掩盖空白区；
- `threshold_registry` 保存 scope、metric、operator/value/unit、不确定度规则、severity、依据/引用、来源类型、生效快照、预注册时间、批准者、状态、变更原因和敏感性计划；语义完整门、标准/应用门、统计充分性门、审计启发式和数据集相对阈值分开；
- 阈值在查看候选排名、模型或实验结果前冻结；更改产生新版本/快照和敏感性分析。观测区间跨阈值时结果为 `inconclusive`；模型最低样本数按任务/目标缺失/期望精度/来源外验证预注册，不能用预测补全扩大观测样本数。

## 9. v0.2 冻结验收标准

只有同时满足以下条件，数据库才可称为“达到可发表、可复核的数据工程冻结质量”；这仍不等于模型、新颖性或实验论文已经完成：

1. 动态发现资产集合与登记/证据排除集合双向差集为零；扫描规则和审计数字可复算；
2. 分别输出文件、源记录、唯一结构、配方、批次、材料状态、试样、测量、汇总观测、曲线、曲线点、计算活动和计算观测的身份定义及 SQL 计数；
3. 所有资产/记录具有治理生命周期六状态；所有观测具有适用的观测语义六维；二者不混用。版本化 `source_scope` 冻结 P0–P4 全集，Eom 主/补充、Nature、WPU-DCR、Pugar 模量、ACS Tg、CIAL、FeatureSpaces、Wiley 及 P3 各 scope 均有成功适配或带证据阻断决定；
4. v0.2 schema 精确声明全部表/字段/Arrow 类型/null/枚举/PK/FK/基数/唯一/CHECK；实际输出、Parquet、DuckDB、审核簿与 schema 对账为零差异；
5. 每个规范/派生记录经无环 lineage 可达原文件和结构化 locator；转换输入/输出与代码哈希完整；
6. 每个关键空值满足字段级 missing XOR；每个数值保留原值/单位、规范值/单位、单位证据和转换事件；
7. 所有主实验观测具有正确 material state、observation subject、property definition、条件、重复/汇总语义；作者仅报告汇总时不虚构成员；合成/加工/测量/计算失败分阶段保存，低性能有效观测不被删除；
8. PolyOmics general 只入库一次、PURT 为可重建视图；PolyGraphMT 长表化；ADEPT 输入不计模拟结果；所有计算观测通过协议/输出/质量门；
9. 所有可用记录具有适用等价/泄漏组；精确配方与近等价组分开。v0.2 不强制训练分区；若生成参考分区，任何受保护组跨分区数量为零；
10. metadata/raw/normalized/derived/aggregate/model 在 retrieve/store/parse/transform/analyze/train/evaluate/redistribute/publish/deploy × actor × purpose × context 下完成全血缘裁决；未知、范围未决、冲突或未满足义务均阻断；
11. `quality_rule` 目录覆盖本规范规则族；所有 blocking issue 为零，warning 均有 owner、证据和处置状态；
12. 科学覆盖矩阵、来源集中度、条件/化学空间空白、失败数据和选择偏倚报告生成；跨来源声明满足第 8.9 节门槛，否则自动收缩 claim scope；
13. PolyOmics/PolyGraphMT/候选、实验标量、曲线和计算活动分别报告，不用计算行数或曲线点夸大实验配方数；
14. 两个隔离目录全量重建得到相同逻辑内容、计数和 schema；同环境确定性文件哈希一致；
15. 快照记录完整代码签名、Git/dirty diff、Python/OS/locale/timezone、依赖锁、参数和规则集；失败构建未覆盖最近冻结快照；
16. 自动化测试覆盖率不低于 90%，并具有 rule-to-test 映射、负例夹具、全量 clean build、QC 和 DuckDB 查询证据；
17. 数据集卡、质量报告、覆盖矩阵、来源引用、许可、排除和审核簿均绑定同一 snapshot，机器对账差异为零；
18. QC JSON 与审核工作簿的问题数量及 `rule_id` 多重集一致，不存在 `UNSPECIFIED`；
19. EHS、价格/供应、加工可行性、失败结果和 novelty dossier 实体可承载主路线所需证据；未知状态不会被解释成通过；
20. GitHub 私人仓库的跟踪文件通过第三方原始数据、许可、密钥、路径、扩展名和大小扫描；只提交允许的代码、配置、清单、文档和小型夹具。
21. 每个主路线材料完成 backbone、network architecture、thermoplastic evidence 和 material-domain 裁决；未知不会自动进入线性 TPU 主域；
22. `source_formulation_id`、精确 `independent_formulation_uid` 和 near-equivalence group 分离；跨来源身份匹配有字段级证据和版本化容差策略；
23. 样本瀑布逐层可复算且差值理由对账；单目标并集、缺失模式、strict joint、formulation-linked joint 和 predicted completion 分别报告；
24. 每个候选声明具有独立的 performance、synthesis、application、novelty 证据级别和 pass/fail/inconclusive；系统不生成无边界的“无人研究”断言；
25. DFT、MD、GC、ML、曲线、图像和实验关系明确标为 multi-fidelity、multimodal、cross-scale、multi-task 或 multi-source；只有同 QoI 且映射/校准成立时使用 multi-fidelity；
26. application profile、需求向量、threshold registry、依据、批准和不确定度裁决完整；阈值变化不静默改变历史快照；
27. 覆盖/偏倚以独立配方、批次和严格交集为分母；来源集中、目标缺失、许可选择、负结果缺失或化学空间空白会自动限制声明；
28. 每个 `allow/allow_with_obligations` 可达已归档、已核验的 rights evidence package；训练、模型发布和部署分别裁决，manual review/deny 不进入对应视图；
29. citation、权利证据、动作决定、署名/许可/修改说明清单和公开 artifact 绑定同一快照；证据撤回、冲突或过期会使旧决定失效；
30. source curator、domain/methods/rights reviewer、QC owner、release manager、snapshot approver 等治理决定留痕；提出者—批准者分离，blocking issue 无法被 waiver 绕过。

## 12. 最小外键图与唯一约束

冻结的 v0.2 schema 至少自动执行以下关系：

- `source_scope.source_id → source`；`source_scope.parent_scope_id → source_scope`；`source_file.source_scope_id → source_scope`；`source_locator.source_file_id → source_file`；scope relation 的 subject/object 均指向真实 scope；
- `record_revision.record_uid → record_registry`；`snapshot_record → dataset_snapshot/record_revision`；`record_source → record_registry/source_scope/source_file/source_locator`；`record_lineage.child/parent_record_uid → record_registry`；
- `material_lot.chemical_id → chemical`；`formulation_component.formulation_id/chemical_id → formulation/chemical`，lot 可选但若存在必须与 chemical 一致；`synthesis_batch.formulation_id → formulation`；
- `event_registry` 是 synthesis/processing/measurement/computation 事件的超类型；`failure_event.event_uid → event_registry`；`synthesis_outcome.batch_id → synthesis_batch`；`polymer_material.batch_id → synthesis_batch`；`material_state.material_id → polymer_material`；processing event 形成无环状态链；
- `observation_subject_registry` 只允许一个受约束 subject extension；`specimen.material_state_id → material_state`；`measurement_run.observation_subject_id/test_protocol_id → subject/protocol`；实验 `observation.measurement_run_id → measurement_run`；
- `sequence_channel/sequence_point/measured_curve/computed_curve → sequence`；`sequence_value → sequence_point/sequence_channel`；measured curve 指向 measurement/subject，computed curve 指向 computational system/activity；
- `aggregate_member → aggregate_observation/record_registry`；只有 `membership_completeness=complete` 时强制 `n_used` 与纳入成员数对账；source-reported unavailable 不虚构成员；
- `computational_activity → computational_system/method_model/event_registry`；`computed_observation.activity_id → computational_activity`；`activity_artifact → activity/artifact`，`artifact_file → artifact/source_file`；
- `rights_fact → rights_evidence_package/source_scope`；`rights_action_decision` 指向 snapshot/target/context/全血缘证据；citation assignment、missing、unit evidence/conversion、quality issue、equivalence membership 和治理决定均指向 registry/source/snapshot 中的真实对象。

最低唯一约束包括：`record_registry(record_uid)`、`record_registry(entity_type,identity_key_sha256,id_algorithm_version)`、`record_revision(record_uid,schema_version,content_hash)`、`snapshot_record(snapshot_id,record_uid)`、`source_locator(source_file_id,locator_hash)`、`missing_value(record_uid,field_name)`、`formulation_component(formulation_id,component_index)`、`sequence_point(sequence_id,point_index)`、`sequence_channel(sequence_id,channel_index)`、`equivalence_membership(group_id,record_uid)`、`rights_action_decision(snapshot_id,target_uid,operation,actor,purpose,rights_object_class,context_profile_id)` 和 `table_build_status(snapshot_id,table_name)`。同哈希文件允许作为有证据的镜像存在，不能简单对 SHA-256 设全局唯一。

历史冻结记录不可物理删除或静默覆盖；纠错通过修订记录、`supersedes`、迁移映射和新快照完成。只有临时构建目录可被替换，最近冻结快照保持不可变。
