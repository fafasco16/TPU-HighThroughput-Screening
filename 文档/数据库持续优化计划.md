# TPU 数据库持续优化 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 在不启动模型训练的前提下，持续增加可追溯的高质量实验、计算和虚拟数据，并把来源、化学体系、配方、协议、性能及不确定度连接成可审计的多保真数据库。

**Architecture:** 原始文件只保存在本地 `数据/原始/`；每个来源在同一目录保存来源元数据、文件哈希和规范化审计清单。`配置/` 负责候选门禁、来源身份和准入策略，`结果/` 只保存轻量总账；所有新增来源先进入审计清单，再由总账生成器统一汇总，不直接写入训练集。

**Tech Stack:** Python 3.11、openpyxl、pandas、PyYAML、pytest、Git/GitHub CLI。

---

## 文件边界

- `配置/候选数据源.yaml`：保存尚未正式接入的数据源、权利、下载文件、哈希、判重和准入建议。
- `代码/审计/候选数据源门禁.py`：重新计算候选评分、许可门禁和 DOI/仓库判重。
- `代码/审计/第五批精选数据.py`：只解析 Data in Brief 形状记忆 PU 与 Zenodo 木质素/TPU 两个来源。
- `代码/测试/test_候选数据源门禁.py`：验证候选表不会绕过权利、判重和下载主机限制。
- `代码/测试/test_第五批精选数据.py`：冻结两个来源的配方、曲线、点数、重复和异常边界。
- `配置/v0.2来源范围.yaml`：为正式接入来源建立稳定 `source/source_scope/source_family/citation` 身份。
- `配置/v0.2资产登记规则.yaml`：只登记允许进入审计的原始文件和派生审计清单。
- `配置/v0.2可训练样本总账来源画像.yaml`：记录来源级数量和任务边界，但保持 `model_ready=0`。
- `代码/生成数据总账.py`：把新增来源的记录级审计清单纳入统一总账。
- `文档/当前数据状态.md` 与 `文档/数据来源与参考文献.md`：更新准确数量和论文式引用。

## 自检

- 计划覆盖实验、计算、虚拟候选、权利、判重、字段映射、引用和全量验收。
- 没有把“文件数、曲线点或轨迹帧”当成独立材料数。
- 没有创建训练划分或物化训练权重。
- 新增目录仍限制在现有五个业务目录内，文档只增加本计划一项。
