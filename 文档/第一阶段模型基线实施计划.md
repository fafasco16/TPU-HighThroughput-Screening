# TPU 第一阶段可训练数据与模型基线 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan.

当前环境没有上述 `superpowers` 子技能，因此执行时使用 Codex 原生并行智能体、测试优先和逐项验收；不改变本计划的边界与验收标准。

**目标：** 在不新增数据源、不伪造结构—配方映射的前提下，把 `结果/可用数据集/` 转化为一套可复现、无明显泄漏、能直接运行的第一阶段基线，并明确哪些数据现在能用于训练、哪些只能作辅助或诊断。

**架构：** 冻结的可用数据集继续作为唯一事实层。`代码/模型基线.py` 提供无第三方机器学习框架依赖的特征、加权 Ridge、指标和端点函数；`代码/生成模型基线.py` 读取发布层、执行配置、生成小型派生结果。`模型/` 只保存配置、报告和结果，不复制 Gold 数据，也不保存不透明二进制模型。

**技术栈：** Python 3.11、Pandas、NumPy、RDKit、PyYAML、pytest/pytest-cov；首版不联网安装 scikit-learn、XGBoost 或 LightGBM。

---

## 一、固定边界

本阶段只做以下四件事：

1. 计算性质：对 `Gold-C` 中有规范结构、单位闭合且独立组足够的目标建立加权常数基线和 Morgan 指纹加权 Ridge 基线。
2. 实验曲线：只对轴含义和单位明确的应力—应变曲线提取保守物理端点；不能确认断裂时，不把“最大观测值”命名为断裂强度或断裂伸长。
3. PUE-643：把 20 个已发布输入字段（18 个连续字段、2 个类别编码字段）到 3 个已发布变换目标作为来源内管线烟雾基线；不逆变换、不声称物理单位、不与通用 TPU 性能混合。
4. 数据门禁：给全部候选目标生成可训练性清单，量化结构/配方/工艺映射缺口；没有成对映射时，多保真增益写为“当前不可估计”。

本阶段明确不做：继续抓取数据、枚举 3212 万个三组分组合、启动 DFT/MD、宣称最终模型、宣称发现新 TPU、把模拟值当实验真值、把曲线点当独立样本。

## 二、目标选择规则

计算主基线首选以下原始标签，大小写别名和不同方法口径不自动合并：

| 目标 | 单位 | 当前用途 | 准入说明 |
|---|---|---|---|
| `density` | `g/cm³` | 结构基线 | 约 6,448 个硬组、2 个来源；`Density` 先单列审计 |
| `bulk_modulus` | `Pa` | 结构基线 | 约 6,447 个硬组、2 个来源 |
| `thermal_conductivity` | `W/(m·K)` | 结构基线 | 约 5,190 个硬组、2 个来源；不与 `Tc` 直接混合 |
| `Rg` | `Å` | 结构基线 | 约 7,558 个硬组、3 个来源 |
| `Tg` | `°C` | 小样本诊断 | 约 261 个硬组、单来源，不作为最终证据 |
| `chi_parameter_water_mean` | 无量纲 | 相容性辅助诊断 | 样本大但单来源，不作为最终 TPU 力学性能 |

最终进入自动训练的目标还必须同时满足：数值有限、规范结构可被 RDKit 解析、至少 100 个硬组、训练/验证/测试均达到配置的最小硬组数。训练和评估必须先使用发布的 `leakage_group` 与 `development_split`，再过滤性质，禁止逐行重新随机切分。

## 四、实施任务

### 任务 1：先写核心函数测试

**文件：**

- 新建：`代码/测试/test_模型基线.py`
- 新建：`代码/模型基线.py`

**步骤：**

1. 为加权均值、加权标准化、加权 Ridge、MAE/RMSE/R²/Spearman 写小型确定性夹具。
2. 为 Morgan 指纹写合法 SMILES、非法 SMILES、确定性和维度测试。
3. 为硬组划分断言写测试：同一 `leakage_group` 不得跨开发集；同一 PUE 数值输入向量必须生成同一派生组。
4. 为拉伸/压缩曲线端点写物理夹具，检查单位换算、梯形积分和“最大观测”命名。
5. 先运行测试确认失败，再实现最小核心函数直至通过；新模块单独覆盖率不得低于 90%。

核心接口固定为：

```python
def featurize_smiles(smiles: str, radius: int, n_bits: int) -> np.ndarray: ...
def fit_weighted_ridge(x, y, weights, alpha) -> dict: ...
def predict_weighted_ridge(model, x) -> np.ndarray: ...
def regression_metrics(y_true, y_pred, weights) -> dict[str, float]: ...
def derive_curve_endpoints(points: pd.DataFrame) -> dict[str, float | str]: ...
```

### 任务 2：配置和计算性质基线

**文件：**

- 新建：`模型/配置/基线配置.yaml`
- 新建：`代码/生成模型基线.py`
- 修改：`代码/测试/test_模型基线.py`

**步骤：**

1. 配置中固定发布 ID、目标名称/单位、Morgan 半径与位数、Ridge 候选 `alpha`、最小硬组数和随机种子。
2. 只读取目标所需列；对唯一规范结构一次性生成特征，非法结构进入可训练性报告而不是静默丢弃。
3. 用训练集拟合加权常数与加权 Ridge；只用验证集选择 `alpha`，测试集只评估一次。
4. 同时输出逐行加权指标和硬组宏平均指标。严格来源外推采用 leave-one-source-family-out：完整留出一个来源族，并从训练侧排除与它共享的硬组；只有训练/测试两侧均达到最小硬组数时才运行，否则记录 `not_estimable`。已发布 `source_holdout_fold` 只保留作诊断标签，因实际仅 0、2、4 三个非空折且极不平衡，不能称五折交叉验证。
5. `逐样本预测.csv.gz` 必须保留 `observation_id`、`leakage_group`、划分、来源、目标、真值、单位、权重、模型和预测，不写入原始 Gold 文件。

### 任务 3：实验曲线端点和 PUE-643 烟雾基线

**文件：**

- 修改：`代码/生成模型基线.py`
- 修改：`代码/测试/test_模型基线.py`

**步骤：**

1. 拉伸曲线只在 `tensile_stress`—`tensile_strain` 且单位明确时提取：50%/100%/300% 应力（仅覆盖时）、最大观测应力、最大观测应变和记录区间能量。只有低应变规定区间至少有 5 个有效点且线性拟合通过门禁时才计算模量；当前 TPUU 曲线不满足，不能强算 Young 模量。
2. 压缩曲线只在 `compressive_stress`—`strain` 且单位明确时提取：10%/25% 应力、割线模量和记录区间能量；单硬组数据标为 `within_source_auxiliary`。
3. 循环拉伸只有在周期边界可稳定识别时才提取回线面积、残余应变和恢复率；否则保留诊断状态，不强行生成数值。
4. PUE-643 从已发布 JSON 条件中解析 18 个数值特征和 2 个类别特征，对完全相同输入向量重新生成派生硬组并固定哈希划分，消除已发现的跨 train/test 重复输入。
5. PUE 原发布行是 `reference_only`、权重为 0；烟雾基线单独使用等权派生视图，绝不回写 Gold 权重。指标显式标注 `transformed_target_only` 和 `within_source_smoke_test`。

## 五、验收标准

- 不新增外部数据，不修改已发布可用数据集字节。
- 每个预测行都能回到原 `observation_id`、来源、引用键和硬组。
- 同一硬组、同一曲线、同一 PUE 输入向量不跨评估折。
- 计算目标至少输出常数与 Morgan-Ridge 两个基线；模型是否优于常数由数据决定，不隐藏负结果。
- 实验端点的名称不超出曲线实际证明范围；单位不明即不计算。
- 报告明确区分计算辅助、实验校准、来源内烟雾测试和未来候选筛选。
- 新代码专项测试通过且覆盖率至少 90%；已有可用数据集检查通过。
- GitHub 仍为私人仓库，提交前工作区无意外文件，推送后本地与远端提交一致。

## 六、完成后的决策门

只有当结构基线在严格测试集和可评估的来源留出上稳定优于加权常数、实验映射缺口被量化、候选构件能接到同一结构表示时，才进入第二阶段候选组合与 Pareto 排序。若来源留出失败或实验映射仍未闭合，下一步优先补映射和实验设计，不通过扩大虚拟行数掩盖问题。
