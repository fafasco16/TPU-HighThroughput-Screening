# TPU 第一阶段模型基线

这里保存第一阶段的配置和可复现结果，不复制 Gold 数据。传统Ridge基线不保存二进制模型；GPU GNN仅保存带代码、配置、输入和权重SHA-256清单的小型PyTorch checkpoint。源码仍在 `代码/`，冻结输入位于 `结果/可用数据集/`。本阶段的作用是检验数据、权重、切分与评估链路是否可靠，不代表已经得到最终 TPU 性能模型或发现了新材料。

目录只保留两层：

```text
模型/
├── README.md
├── 配置/
│   └── 基线配置.yaml
└── 基线结果/
    ├── 目标可训练性.csv
    ├── 指标.csv
    ├── 逐样本预测.csv.gz
    ├── 实验曲线端点.csv
    ├── 运行清单.json
    └── 基线报告.md
```

## 运行

在仓库根目录执行以下一条命令生成全部结果：

```powershell
uv run python .\代码\生成模型基线.py
```

生成后，用下面一条命令校验冻结发布层以及现有结果的 SHA-256；该命令不训练，也不写文件：

```powershell
uv run python .\代码\生成模型基线.py --检查
```

默认读取 `模型/配置/基线配置.yaml` 和发布版 `tpu-usable-2026-07-21-v1`。修改目标、门槛、Morgan 参数或 Ridge 候选值后，应重新生成结果，不能沿用旧指标。自定义目录时可使用脚本提供的 `--配置`、`--发布目录` 和 `--输出目录` 参数。

## 结果怎样读

`目标可训练性.csv` 是先看的一张表。它按 Gold-C 的原始“性质—单位”组合列出总行数、可训练行数、有效结构与正权重行数、无效结构行数、结构身份状态、恰有两个 `*` 的重复单元行数、train/validation/test 硬组数、primary 硬组数、来源族数、可运行的来源留出次数、引用键以及准入状态。`fair_primary_evaluation` 和 `training_status` 决定该目标能否进入公平基线；`multifidelity_pairing_status=not_established` 表示目前尚无足够闭合的计算—实验成对映射。

`指标.csv` 保存每次评估的汇总结果。`evaluation_scheme` 区分发布开发划分、逐来源族留出和 PUE 派生硬组烟雾测试；`training_mode`、`model_name`、`target_name`、`unit` 和 `evaluation_split` 说明比较对象；`aggregation_level` 同时给出逐行加权与硬组宏平均口径；`n_rows`、`n_groups`、`mae`、`rmse`、`r2`、`spearman`、`selected_alpha` 和 `status` 用于判断结果是否可估计。MAE、RMSE 和 R² 使用相应层级的权重，Spearman 是正权重观测上的未加权秩相关。解释指标时必须连同 `evidence_scope` 与 `target_semantics` 一起引用，不能只摘一个较好的 R²。

`逐样本预测.csv.gz` 用于复核误差和追溯数据。每行保留 `evaluation_id`、评估方案、训练模式、模型名、`observation_id`、`leakage_group`、发布划分、来源与来源族、结构身份状态、结构中的 `*` 数量、真值、单位、权重、预测值、所选 alpha、证据范围、目标语义、来源定位和引用键。它是派生结果，不是新的独立实验数据。

`实验曲线端点.csv` 每条发布曲线一行。固定追溯字段包括曲线、来源、配方、样品、硬组、开发划分、点数、来源定位和引用键；`endpoint_status`、`curve_type` 和 `release_model_ready` 说明是否通过门禁。通过时才按曲线类型出现最大观测应力/应变、记录区间能量、指定应变应力、压缩割线模量或低应变拟合状态等字段。空值通常表示曲线未覆盖该区间或门禁未通过，不应补零。

`运行清单.json` 是复现入口，记录发布 ID、配置快照与哈希、输入和输出文件哈希、软件版本、行数、Git 基线提交、PUE 处理元数据、多保真状态以及确定性写出约定。`run_started_utc` 和 `runtime_seconds` 是允许变化的运行信息；其余派生文件应能由相同输入与配置重建。

`基线报告.md` 是供人工阅读的本轮摘要，说明目标准入、计算基线、曲线端点、PUE 烟雾测试、多保真缺口、实际涉及的来源和引用键。论文写作仍应回到原始来源，不应只引用这份自动报告。

## 训练、权重和防泄漏规则

`primary_only` 只用 `usage_mode=primary_train` 的训练折拟合；`primary_plus_aux` 允许训练折再加入 `auxiliary_train`。两种模式的验证集和测试集始终只使用 `primary_train`，因此它们比较的是“辅助数据是否改善同一主证据评估”，不是把模拟辅助值当成实验真值。

Gold-C 拟合和逐行指标沿用发布的 `recommended_loss_weight`。同一硬组的宏平均先在组内按该权重聚合，再让各硬组等权，避免重复行或高密度模拟序列主导结论。权重为零、结构无效、数值非有限或 `model_ready=false` 的记录不会静默进入计算基线；它们仍会在可训练性审计中留下原因。不要自行把辅助行权重改成 1，也不要按曲线点数或重复次数放大样本贡献。

常规评估严格沿用发布的 `development_split` 和传递闭包后的 `leakage_group`，不再逐行随机切分。Ridge 的 alpha 只在 validation 上选择，test 只评估一次。`leave_one_source_family_out` 会完整留出一个来源族，并从训练和验证侧排除与留出族共享的硬组；只有训练、验证和留出组数均达到配置门槛时才运行。发布层稀疏的 `source_holdout_fold` 只可作诊断标签，不能写成五折交叉验证。

## 曲线端点门禁

只有发布层已经标为 `model_ready`，且应力轴、应变轴和单位都明确的曲线才派生物理端点。拉伸仅接受 `tensile_stress`—`tensile_strain`，压缩仅接受 `compressive_stress`—应变，并要求点序和符号约定可解释。单位不明、点序重复、应变轴非单调或压缩符号不受支持时均关闭计算。

50%、100%、300% 拉伸应力和 10%、25% 压缩应力只在曲线实际覆盖对应区间时插值。低应变模量还需满足近零起点、足够跨度、至少五个有效点、小截距和线性拟合门槛；未通过时只保留状态，不强算 Young 模量。循环拉伸在周期边界未可靠分割时只标记 `cycle_segmentation_required`。`max_observed_*` 和 `recorded_energy_density_*` 只描述已记录区间，不能改名为断裂强度、断裂伸长或完整韧性。

## PUE-643 的限定用途

PUE-643 原发布行保持 `reference_only` 且 Gold 权重为 0。本脚本只建立一个不回写 Gold 的等硬组权重派生视图：用完整 20 字段输入向量生成稳定硬组和固定哈希划分，`Form_Method`、`PMStep` 作为类别特征，其余 18 个字段作为数值特征。相同输入向量不得跨折，类别水平只从训练折学习。

`logYM`、`logTS`、`logEB` 仅用于 `within_source_smoke_test`，并明确标记为 `transformed_target_only`。当前公开字段不足以把这些变换目标可靠恢复到有明确单位的物理量，因此本仓库不做逆变换，也不把它们与通用 TPU 强度、模量或伸长率混合。该测试只能证明解析、分组、训练和评估管线能够闭环，不能作为新体系外推证据。

## 来源、引用和许可

从 `逐样本预测.csv.gz` 或 `实验曲线端点.csv` 取得实际使用行的 `source_id`、`source_locator` 和 `citation_keys`；再到 `结果/可用数据集/来源与引用.csv` 按 `source_id` 查 `source_title`、稳定标识、`license_status` 和完整引用键，最后在 `文档/数据来源与参考文献.md` 找到相同 `citation_key` 的正式文献或数据集条目。论文应引用原作者和固定版本，不能只引用本项目。

许可判断必须按实际来源和用途逐项进行。`license_status` 未声明、待复核或限制商业使用时，科学参考价值不等于获得训练、再分发或部署授权；不要把不同来源的许可证合并成一个笼统许可。公开模型、数据附件或商业部署前应重新按所用行的唯一来源清单审查。

## 正确与错误用法

正确做法包括：在冻结发布上比较加权常数与 Morgan-Ridge；同时报告逐行加权和硬组宏平均结果；分开报告 `primary_only` 与 `primary_plus_aux`；把来源族留出作为严格外推检查；把曲线端点称为“最大观测”或“记录区间”；让每个结果回溯到 observation、硬组、来源和引用。

错误做法包括：逐行随机切分同一结构、曲线或配方；把曲线点数当成独立材料数；把 Gold-C 模拟值写成 Gold-E 实验真值；把 PUE 的对数目标逆变换后宣称有确定物理单位；把辅助训练行混进验证或测试；只挑较好指标而隐藏常数基线、失败门禁或来源留出负结果；从重复单元 SMILES 直接宣称已表示完整配方、分子量和工艺。

## 阶段门

本阶段只回答三个问题：传统结构基线能否在严格测试和可评估的来源族留出上稳定优于加权常数；辅助数据是否在不改变主证据评估集的情况下带来可复现增益；实验结构—配方—工艺映射缺口有多大。当前多保真增益默认是 `not_established`，不能用更多虚拟行数替代成对映射。

只有上述检查通过，并且候选构件可以接入同一结构表示，才进入下一阶段的候选组合、Pareto 排序和小规模 DFT/MD 复核。若来源外推失败或实验映射仍未闭合，下一步应先补映射与实验设计，而不是继续扩大虚拟数据量或提前宣称得到高性能 TPU 体系。

## GPU图神经网络基线

`代码/GNN数据.py`把冻结的`计算观测.csv.gz`转换为带节点、键和发布元数据的分子图；默认只接受`Rg`、`density`、`bulk_modulus`和`thermal_conductivity`，`Tg`仍关闭。节点特征9维，键特征4维。同一`leakage_group`跨折、非法结构、重复观测、非正权重或单位不闭合都会直接报错，不能静默清洗后继续训练。

`代码/GNN模型.py`实现不依赖PyG的轻量消息传递网络；`代码/训练GNN基线.py`分别训练`primary_only`和`primary_plus_aux`。训练集拟合目标标准化，validation只负责早停和checkpoint选择，test只在checkpoint确定后评估一次。输出目录包含checkpoint、`指标.csv`、`逐样本预测.csv.gz`和`运行清单.json`，运行清单记录输入、配置、代码和权重SHA-256。

Ubuntu L40运行命令见`计算/独立实例环境.md`。本地无CUDA时仍可运行数据层和纯逻辑测试；正式结果必须与`模型/基线结果/指标.csv`中相同训练模式、目标、测试口径及聚合层级的Morgan-Ridge逐项比较。只有内部测试和可估计的来源族留出都稳定改善时，GNN才可作为候选排序辅助；否则保留负结果并继续使用Ridge。

## 阶段配方Pareto

`代码/生成阶段配方筛选.py`消费构件级xTB系综描述符，输出`计算/阶段筛选/`下的48行阶段配方表、第一前沿和报告。当前82个已完成构件对应40条可比较配方、8条闭门配方、25条阶段第一前沿和8个确定性多样性簇。所有行均标记`stage_only_not_final`和`no_performance_claim`；目标是NCO/OH位点电荷、位点可及性、构象不确定度及计算负担代理，不是强度、韧性、反应速率或最终可合成性。最后两个CREST构件补齐后必须从完整构件批次重算，阶段文件不得回写Gold真值层。
