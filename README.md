# TPU 高通量筛选数据库

本项目建立一个用于发现新型高性能 TPU/TPUU 体系的多保真数据库。数据可以来自实验、DFT、MD 和可靠的虚拟候选库，但必须保留来源、方法、可信度和不确定度，最终由真实合成实验验证。

## 当前结论

- 已登记 60 个来源范围、3,748 条审计清单记录；这些记录包含来源、曲线、标量和运行，不等于 3,748 个独立材料。
- 已有 30 个核心配方键、27 个可确认批次和 217 条键控实验曲线。
- 已有 1,071 个带原始 SMILES 的 SMiPoly 虚拟候选；计算参考清单228行，其中第六批新增148条实验/计算汇总观测，106条通过当前科学门。
- 当前最大的缺口是：核心实验曲线尚未与完整单体结构、定量配方和工艺条件闭合。
- 因此当前仍未创建训练集；下一步先物化多保真 Gold 数据，而不是继续无差别增加来源。

Gold 的准确字段、实验/计算/虚拟数据如何共同进入筛选体系，见 [Gold 数据集定义](文档/Gold数据集定义.md)。现有数据能填多少、还缺什么，见 [当前数据状态](文档/当前数据状态.md)。

如果只想判断“现在有什么、能不能用”，只看三个文件：

1. `文档/当前数据状态.md`：人可读的数量与缺口；
2. `结果/数据规模总账.csv`：每个来源的机器可读汇总；
3. `结果/样本清单.csv`：逐记录 `Gold` 分层、来源、谱系和权重上限。

## 目录

仓库只保留五个业务目录：

```text
数据/       原始、暂存、规范、派生、快照；大文件只在本地
代码/       构建、质量控制、来源接入和测试
配置/       数据源、结构定义、准入规则和来源清单
文档/       Gold 定义、当前状态、数据来源与参考文献
结果/       机器可读的数据总账和审核导出
```

GitHub 私人仓库只保存代码、配置、文档和轻量总账，不上传出版商附件、受限数据或大型原始文件。

## Gold 的三类数据

- `Gold-E`：真实实验配方、制样、测试条件和性能，是最高可信标定层。
- `Gold-C`：来源可靠、协议完整、可复现的 DFT/MD 数据，可作为描述符、预训练数据或低保真标签。
- `Gold-V`：可合成的虚拟候选，保存结构、反应规则、可合成性、预测值和不确定度，用于扩大候选空间。

三类数据共享化学物、配方和候选 ID，但不会把模拟值无标记地伪装成实验值。训练权重以后按来源、任务匹配、实验映射和不确定度校准，不按文件数、曲线点数或模拟帧数决定。

## 最小运行入口

```powershell
uv sync --extra dev
.\.venv\Scripts\python.exe 代码\生成数据总账.py
.\.venv\Scripts\python.exe 代码\run_pipeline.py manifest
.\.venv\Scripts\python.exe 代码\run_pipeline.py build --version v0.1
.\.venv\Scripts\python.exe -m pytest 代码\测试 -q
```

默认来源清单位于 `配置/清单/来源清单.csv`，结构定义位于 `配置/结构定义/`，数据库输出位于 `数据/规范/`、`数据/快照/` 和 `结果/`。

## 数据与引用

每个来源必须记录 DOI/URL、版本、访问日期、许可证、原文件哈希和原始定位。论文式参考文献统一维护在 [数据来源与参考文献](文档/数据来源与参考文献.md)。
