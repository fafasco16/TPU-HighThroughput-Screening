# TPU 构件量化计算

本目录保存可复现任务输入和调度入口，不保存大体积运行轨迹。当前阶段为 `CREST 3.0.2 + GFN2-xTB 6.7.1` 的 Tier-1a 构象筛选；48 条配方去重为 86 个唯一构件任务。84个构件通过初始三维结构门；2个稠合笼状/稠合芳环二异氰酸酯无法由当前RDKit ETKDG流程可靠嵌入，保留为 `blocked_rdkit_3d_embedding`，不会用二维假结构替代或从总数中消失。

```powershell
uv run python 代码\生成DFT任务.py
uv run python 代码\生成DFT任务.py --检查
uv run pytest 代码\测试\test_DFT任务.py -q
```

目录保持两层：

```text
计算/
├── README.md
├── 服务器环境.md
├── DFT任务清单.csv
├── DFT任务发布清单.json
├── 运行CREST数组.sh
└── 初始结构/
    └── 通过三维结构门的XYZ
```

远端运行目录为 `/home/zhanhao/TPU高通量筛选`，沿用仓库的 `代码/候选/计算` 浅层结构；运行轨迹与Slurm日志分别进入 `计算/结果` 和 `计算/日志`。完整轨迹只保存在服务器；汇总表和重要派生描述符通过哈希核验后再回填仓库。密码和其他凭据不得写入任何文件。

初次提交按异常的节点配置申请了128 CPU；排队观测显示实际运行作业多为16–64核，因此Job 8307在不取消、不丢失排队年龄的前提下降为32核。提交脚本仍可能启动更多包装器进程，但包装器依据`SLURM_CPUS_PER_TASK`文件锁最多允许8个CREST任务同时计算，每路使用4线程。它先并行运行索引0和44的烟雾测试，通过后才进入全量。完成标准不是 Slurm 显示 `COMPLETED`，而是包装器同时确认退出码为0、`crest_conformers.xyz`存在、输入哈希匹配，并写入 `运行状态.json`。失败任务保留旧尝试目录，重新提交不会覆盖旧证据。

CREST结束后由`发布CREST结果.py`逐任务核验状态、输入/输出哈希和构象文件，只接受`completed`与预期的`blocked_input_geometry`终态。发布器生成`CREST最终汇总.csv`、确定性`CREST精简结果.tar.gz`和`CREST结果发布清单.json`；任何running、pending、failed或哈希不一致都会关闭发布门。

`CREST系综分析.py`进一步计算298.15 K电子能代理权重、有效构象数、离散构象熵、主构象占比和1/3/6 kcal mol⁻¹窗口计数。该层仍是GFN2-xTB构象代理，不是实验热力学布居。下一阶段命令、字段和失败门见[xTB系综描述符实施方案](../文档/xTB系综描述符实施方案.md)。
